# BT 传输体验 · 工程实验协议（E0–E3）

> 本轮**不运行**任何实验。本文只写出协议、前置条件、样本与环境清单、交叉顺序、分析方法、中断规则与所需授权。
> 所有阈值、`tau`、样本量在 run 前固定；本轮给出的数值一律标为**候选默认**，正式实验前必须由 pilot 校正并冻结。
> 指标定义见 `metrics.csv`（`metric_id` 在本文件内直接引用）。机制与证据见 `README.md` 与 `sources.csv`。

---

## 0. 统一实验规则（适用于 E0–E3）

1. **一个实验单位只跑一个待测方案**：每个独立性能 run 只运行一个待测实现/方案；run 结束并确认旧任务、连接、socket、文件句柄释放后才启动下一个 run。
2. **共同瓶颈实验的单位是完整 session/swarm**：多任务或多客户端竞争带宽时，把整个 session/swarm 作为一个实验单位；其内部任务与 peer 是**嵌套观测**，不是独立重复。
3. **禁止伪对照**：不得让两份同 infohash、同一 session、或两个客户端抢带宽却声称是独立对照。
4. **冷暖必须可证**：先验证 peer/metadata/fastresume 等缓存可控，明确区分「冷内容 / 冷连接 / 冷发现」与暖启动；只换目录不构成完全冷启动。
5. **公网不可彻底重置**：E3 的远端状态无法重置，该限制必须在每个 run 的元数据中保留，不得事后声称已消除。
6. **跨实现配对**：使用同一合法工作负载、可比有效配置、固定构建信息；按**随机 AB/BA 分块**配对，而不是固定先 A 后 B。
7. **样本规划**：每个核心条件先规划 **6 个独立配对**，分散到 **至少 3 个时间块**（用于估计方差与顺序效应，不是统计充分性保证）。正式样本量由 pilot 方差与预先指定效应计算，公式见 §5.3。
8. **采样不是重复**：1s 快照不是独立实验重复；统计单位是独立 run / session / swarm。
9. **主终点固定**：wall completion（`M-COMPLETE-01`）、首个已验证 piece 时延（`M-START-03`）、固定观察期内完成比例（`M-START-04`）、`V(tau)/B`（`M-GOODPUT-05`）。前台交互延迟与资源占用是**护栏**（`M-GUARD-01`…`M-GUARD-08`）。
10. **`tau` 的语义**：在 experiment 开始前固定，是**观察预算**，不是产品 SLO。固定窗口 goodput（`M-GOODPUT-03/04`）只作诊断辅终点，不能用某个 5 分钟赢家代替整程结论。
11. **报告口径**：每 run 原始值 + 配对差/比值 + 中位数/IQR；样本允许时按独立配对块 / session / swarm 做 bootstrap 区间。
12. **删失与失败**：行政截止未完成记**右删失**；终止性错误与用户取消分作**竞争事件**或单列。不删除慢失败 run，不把超时上限当真实完成时间，不仅比较成功者均速（见 `README.md` 统计反例）。
13. **阈值不凭单例**：达标阈值不凭单个 ISO 试验定；正式实验前由**可实现容量基线**与**用户体验目标**共同设定。
14. **鲁棒性另设臂**：手动 pause、重启、网络切换另设鲁棒性实验臂；若污染了无干预整程，保留该 run 并标记，**不能只扣暂停时间就恢复因果可比性**。
15. **硬约束不回退**：减小预算时的已有连接保护、private 规则、校验（hash 必须做）、用户限速是硬约束，任何实验不得为了吞吐取消它们。
16. **只输出候选实验**：本协议不自动应用任何参数。

### 0.1 隔离与不向公网传播

- 受控 swarm **必须靠隔离网络或明确出口限制**确保不向公网传播：独立 network namespace / host-only bridge + 出口 allowlist（仅放行受控对端地址）+ 依赖检测（确认无外部 peer 进入）。**仅靠 torrent 的 `private` 标志不构成隔离**。
- E1 需要 DHT 时使用**隔离自有 DHT**（自有 bootstrap 节点 + 拒绝公网节点），**绝不**把 private 种子或受控内容发布到公共 DHT。
- **数据面实验固定初始候选与供给**；只有发现机制实验才让 tracker/DHT/PEX 路径成为操纵量。
- 出口带宽如需限幅，用出口侧整形（qdisc）在**独立于被测主机的中间盒**上做，避免与被测进程争 CPU。

### 0.2 原始数据与匿名化

- 原始 run 数据本地受限保管；公开结果**不含** IP / peer ID / passkey / cookie / token / 完整 magnet。
- 必要的 peer 去重只在 run 内用**随机盐**标识（`salt` 随 run 生成、run 结束即弃）。
- 不新增匿名遥测；本协议的全部指标仅本地采集。

## 2. E0 · 观测语义与正确性审计

**目的**：先证明「数据说的是它声称说的东西」。这一阶段不产生性能结论，只产出**口径审计报告**与已修正的采集前置。

### E0-A 逐字段维护点与重置作用域映射
- **假设**：现有快照字段（`M-CONN-01`、`M-PEER-02`、`M-RATIO-02`、`M-RECOVER-04`）中至少有一部分的**重置作用域**与文档/直觉不一致，导致跨 epoch 差值不可加。
- **操纵量**：无（只读审计）。逐字段标注：维护点（哪个结构体/哪一行）、作用域（per-peer / per-task / per-session / per-process）、生命周期（point-in-time / 当前 torrent 生命周期累计 / 本次进程启动以来）、重置触发条件（session 重建、torrent 重加、fastresume 恢复、pause/resume）。
- **固定量**：pinned rqbit `6f9d64b310ecb560990315af3c60df3111eec8e7`、FD 构建号、审计只读不改。
- **主终点**：字段映射表覆盖率 100%（每个被实验引用的字段都有维护点与作用域）；不一致项数与其处置。
- **反例**：若某字段在 session 重建后归零而任务 DB 仍累计，则「跨 epoch 差值」不可加——这正是 `M-RECOVER-04/_05` 要防的错误。审计必须能**主动找出**这种字段，否则审计无效。
- **资源护栏**：审计不启动下载；只读源码与快照。
- **所需授权**：本地只读仓库与代码阅读权限（已有）。不启动网络。

### E0-B 计时口径独立验证
- **假设**：`g_time_now` 类墙钟在不同机器/不同时刻不可比；只有**单调时钟**在同主机内可比。
- **操纵量**：在受控本地场景下人工注入可测量的停顿（例如本地磁盘 I/O 阻塞），对比单调时钟与墙钟读出的阶段耗时差。
- **固定量**：单主机、单进程、无网络。
- **主终点**：阶段耗时在单调时钟下的可重复性（同一注入量的重复测量离散度）。
- **反例**：若阶段耗时依赖 NTP 步进而变化，则任何跨主机「单向时延」推断都不成立；报告必须显式拒绝该推断。
- **资源护栏**：无外部负载。

### E0-C 紧凑地址解析与来源去重独立验证
- **假设**：compact peer list 的 IPv4 = **6 字节**、IPv6 = **18 字节**；解析错误会静默产生错误地址或错位切分。
- **操纵量**：构造已知地址集合的合成 tracker 响应与 DHT 响应（离线，不联网），覆盖：仅 IPv4、仅 IPv6、混合、长度非 6/18 倍数的畸形输入、同一地址由两个来源返回。
- **固定量**：离线 fixture；不联网。
- **主终点**：解析结果与输入集合逐项一致；畸形输入被**拒绝**而不是产生部分地址。
- **反例**：同一 peer 被 tracker 与 DHT 均发现时，去重后 peer 总数必须为 **1**；两个来源的 reachability 各可为 1，但**不得把两份字节加和**，也不得把 peer 计成 2。若实现做不到，`M-DISC-02/_03` 的口径必须改写而不是掩盖。
- **资源护栏**：纯离线单元级验证。

### E0-D 握手阶段与进度/字节口径验证
- **假设**：当前 `connections`/`errors` **不等于** BitTorrent/MSE 握手成功/失败计数；`fetched` 也不是「唯一有效文件进度」。
- **操纵量**：
  - 握手：构造 TCP connect 成功但握手失败的确定性场景（本机受控对端在 accept 后立刻关闭、发送畸形握手、发送错误 info-hash），确认计数表现。
  - 进度：构造「已收 payload 但 piece 尚未验证」的窗口，确认 `M-STAB-05` 能把该窗口与真停滞区分。
  - 字节：核对 `M-RATIO-01` 的 wire/fetched/checked/validated 四者能否在同一窗口对齐。
- **固定量**：本机受控对端；不联网。
- **主终点**：任一条 transport 成功 + 握手失败的 attempt 只增加 **transport success**，不增加 **handshake success**（`M-CONN-02` vs `M-CONN-07`）。
- **反例**：若实现把 TCP connect 成功计入握手成功，则 `M-CONN-07` 的分子被污染，其任何「成功率上升」结论都无效。
- **资源护栏**：受控对端数量固定、总连接数有上限。
- **所需授权**：本地环回/受控对端的连接与握手（不涉及公网）。

### E0 退出条件
- 每个被 E1–E3 引用的 metric 都有：维护点、作用域、重置规则、可用性判定（`available`/`partial`/`missing`）。
- 已发现的不一致项全部登记（进入 §1 缺口表或修正口径）；未解决项对应的实验臂**不开跑**。

## 3. E1 · 受控传输基线

**目的**：在因果可控的 swarm 上量化「调度/预算/流水线/磁盘」各自的贡献，为 E2/E3 提供基线。

### 3.1 受控 swarm 构造

| 项 | 规格 |
|---|---|
| 内容 | **自有生成**内容（确定性伪随机；可含可压缩与不可压缩两部分，用于区分校验/磁盘与网络瓶颈） |
| 目录 | 每个 run 独立目录；不用共享目录冒充冷启动 |
| piece 大小 | 固定（候选默认 1 MiB；需覆盖 256 KiB 与小 piece 对照一次） |
| 初始 piece 分布 | **已知且固定**：seed 持有 100%；另有计划内的「稀缺 piece」场景，由显式撤下某些 piece 的 seed 制造 |
| seed 组成 | 起步：1 个完整 seed。随后：多个异构 seed（不同客户端、不同块大小行为、不同上传限速） |
| tracker | 自建受控 tracker（记录 announce 次数与返回的 peer 列表） |
| DHT | 默认关闭；需要时用**隔离自有 DHT** |
| 出口 | 独立 network namespace / host-only bridge + egress allowlist；依赖检测确认无外部 peer |

### 3.2 E1 实验卡

**E1-1 单任务 · 准入预算与尝试速率**
- **假设**：`bt_peer_limit`（128..512）与 `BT_SESSION_PEER_LIMIT`（128..4096）通过「许可被半开拨号占满」限制可用 peer 数；在候选不可达率高的受控 swarm 上，抬高预算会提高有效 peer 数与 goodput，但在候选充足且可达率高的 swarm 上**不**产生收益（`M-BUDGET-*`、`M-CONN-05`）。
- **操纵量**：`bt_peer_limit` ∈ {128, 256(default), 384, 512}；`bt_session_peer_limit` ∈ {1024(default)} 固定；准入尝试速率（connecting budget = `(session/4).clamp(1,128)`）单独一臂。
- **固定量**：内容、piece 大小、seed 数、初始 piece 分布、`connect_rate`、backoff 参数、uTP/MSE 开关、上传限速、磁盘、`tau`。
- **主终点**：`M-COMPLETE-01`、`M-START-03`、`M-GOODPUT-05`（`V(tau)/B`）；辅：`M-BUDGET-03/04`、`M-PEER-01`。
- **反例**：若预算抬高后**满额时长比例仍高**且 effective peer 数不增，则「顶格」并不证明该闸门是瓶颈——此时收益应来自别的限制（磁盘/请求窗口/对端供给）。必须能观察到并报告这种「抬了没用」的结果。
- **资源护栏**：`M-GUARD-03/04/05`；RSS 超基线 2× 或 FD 超 rlimit 80% → 中断 run。
- **所需授权**：受控 swarm 构造 + 隔离网络 + 多轮 run（**另行授权**）。

**E1-2 单任务 · 请求窗口与流水线**
- **假设**：在途有效请求字节需覆盖「路径反馈时延 × 速率需求」；请求窗口不足会在高 RTT 或高丢包下先于带宽成为瓶颈，但在低 RTT 高带宽下不是瓶颈（`M-REQ-01/02/03`）。
- **操纵量**：请求窗口（若 pinned rqbit 该值不可配则本臂**降级为诊断对照**并记 `missing`）；块大小（16 KiB vs 32 KiB vs piece 大小）。
- **固定量**：同 E1-1；RTT/丢包固定为受控档（见 E2）。
- **主终点**：`M-GOODPUT-01/03`；辅：`M-REQ-01/02`。
- **反例**：BDP 公式给出的是**下界需求**，不是最优 peer 数；若把 BDP 直接当最优 peer 数，会在上传受限的 swarm 上过度拨号并抬高排队延迟。报告须显式区分：请求窗口 / 拥塞窗口 / 接收缓冲 / 磁盘 四类限制，不合并成一个结论。
- **资源护栏**：`M-GUARD-07/08`（磁盘队列与校验 CPU）；磁盘队列延迟 > 2000 ms 持续 ≥30 s → 中断。
- **所需授权**：同 E1-1。

**E1-3 单任务 · piece 选择与 endgame**
- **假设**：pinned rqbit 的实际 piece 选择策略（需在 E0 确定，禁止猜测）在稀缺 piece 场景下决定长尾长度；rarest-first 类策略改善完成时间但在早期可能压低上传（互惠未建立）。
- **操纵量**：策略开关（可配则操纵，不可配则只对照「受控稀缺 piece 分布 × 多样 seed」）；endgame 开/关（若可配）。
- **固定量**：seed 供给、稀缺 piece 集合、候选可达率。
- **主终点**：`M-COMPLETE-03`（tail time，95%→完成）；辅：`M-RATIO-02`（上传贡献）、`M-REQ-06`（endgame 重叠）。
- **反例**：若 tail time 无差别而**上传**显著下降，则该策略在「完成时间」上无收益却在「长期做种贡献」上有代价——两个目标不一致时必须同时报告，不得只报完成时间。
- **资源护栏**：`M-GUARD-08`。
- **所需授权**：同 E1-1。

**E1-4 多任务竞争（session 作为实验单位）**
- **假设**：session 级预算在多任务间共享；单任务视角的「每任务额度」不成立。公平性取决于需求归一化方式与排队策略。
- **操纵量**：任务数 1 → 4；任务需求配置（等大 / 1:1:1:10 / 一任务近乎完成）；是否启用任务级上限。
- **固定量**：同一 session、同一 swarm 集合、同一采样窗；**整个 session 作为一个实验单位**。
- **主终点**：`M-RATIO-05`（需求归一化 goodput）、`M-RATIO-06`（公平性与饥饿时长）；辅：`M-BUDGET-03/04`。
- **反例**：Jain 指数必须在任务目标/容量可比或已归一化时才用；若某任务已接近完成而仍在争带宽，「不公平」可能是**正确**行为。未归一化的 Jain 会给出错误结论。
- **资源护栏**：`M-GUARD-04/05/07`。
- **所需授权**：同 E1-1。

**E1-5 上传限速与互惠**
- **假设**：上传额度与 rechoke 行为影响下载 goodput（互惠）与长期做种贡献，且在大 swarm 与单 seed swarm 上机制不同。
- **操纵量**：上传限速档（无限制 / 与下行对称 / 显著低于下行）；是否暂停做种（对照）。
- **固定量**：同 E1-1；对端集合固定。
- **主终点**：`M-GOODPUT-01`、`M-RATIO-02`、`M-RATIO-07`（TCP/uTP 份额）。
- **反例**：若「无限制上传」的 goodput 不高于「对称限速」，则互惠在该 swarm 上不是主因（可能是单 seed 供给了全部数据）。此时不得声称「上传换速度」。
- **资源护栏**：`M-GUARD-02`。
- **所需授权**：同 E1-1。

**E1-6 磁盘背压**
- **假设**：磁盘队列/校验会通过背压限制网络吞吐；在机械盘或受限 I/O 下先于网络成为瓶颈。
- **操纵量**：目标目录介质（NVMe / SATA SSD / HDD）；是否启用 cgroup I/O 上限；校验并发。
- **固定量**：网络条件与候选供给固定，使网络不成为瓶颈。
- **主终点**：`M-GUARD-07/08`；`M-GOODPUT-01`（验证磁盘是否成为限制）。
- **反例**：若把「磁盘限速」下的 goodput 当成网络极限，会低估传输能力；反之若把网络受限 run 当成磁盘结论，也会错。必须用「改变磁盘不改变网络」的单变量对照识别。
- **资源护栏**：`M-GUARD-07`。
- **所需授权**：本机磁盘条件与 cgroup I/O 控制（**另行授权**）。

### 3.3 E1 工具与权限清单（**本轮不安装、不启动**）
- 受控 tracker（自建；记录 announce 频率以遵守正常客户端行为）

- 只读内核/磁盘采样脚本
- 独立交互护栏探测端
- cgroup I/O 限幅
- 全部工具在 E1 启动前单独授权；**不得在研究批准后自动安装或启动**。

## 4. E2 · 网络边界与协议互操作

**目的**：在 E1 基线上，把网络条件与协议选择作为操纵量，找出「哪个限制在哪种网络下才是瓶颈」。

### 4.1 共同固定量
E1-1 的全部固定量，加上：受控中间盒（决定 RTT/丢包/带宽不对称）、候选集合与供给、协议开关的**有效配置**（不是 UI 显示值；E0 须确认哪些设置需要重建 session 才生效）。

### 4.2 E2 实验卡

**E2-1 RTT 与丢包**
- **假设**：存在一个「阶段转换点」：在低 RTT 低丢包下带宽/供给限制，在较高 RTT 或丢包下请求窗口/拥塞控制限制。
- **操纵量**：RTT ∈ {5, 30, 100, 250} ms（单向叠加）；丢包 ∈ {0, 0.1, 1, 3} %。
- **固定量**：带宽对称与不对称各固定一档；协议与预算固定。
- **主终点**：`M-GOODPUT-01/03/04`、`M-REQ-02`；护栏 `M-GUARD-01`。
- **反例**：若 RTT 升高后 goodput 不变，说明**不是** BDP/流水线限制（可能是供给或磁盘）。必须能报告这种「无转换」的结果，不得默认流水线是原因。
- **资源护栏**：`M-GUARD-01/02/03`。
- **所需授权**：受控中间盒与整形。

**E2-2 带宽不对称**
- **假设**：下行受限与上行受限的根本瓶颈不同（上行受限会压低互惠与上传贡献）。
- **操纵量**：下行:上行 ∈ {10:1, 4:1, 1:1}，各自绝对值两档。
- **固定量**：RTT/丢包固定一档；预算固定。
- **主终点**：`M-GOODPUT-01`、`M-RATIO-02/07`。
- **反例**：若上行受限时 goodput 反而更高（因为少了上传抢占），不得解释为「上行越慢越好」——这要求同时报告上传贡献与长期做种代价。
- **所需授权**：同 E2-1。

**E2-3 协议选择：TCP-only / uTP-only / 混合**
- **假设**：uTP 在某些 NAT 环境下提高可达性（更多可连 peer），但 LEDBAT 的**低干扰目标**与具体实现不同，混合流下的公平与 goodput 取舍需实测；uTP 在本地环回/低 RTT 下相对 TCP 无优势。
- **操纵量**：transport 开关（TCP-only / uTP-only / 两者）；对端 transport 能力构成（受控对端分别只支持一种）。
- **固定量**：RTT/丢包/带宽固定；候选集合固定；`utp_loss_multiplier`/目标时延若可配则单独一臂，否则记 `missing`。
- **主终点**：`M-CONN-02/07`（可达性与握手）、`M-GOODPUT-01`；护栏 `M-GUARD-01`（uTP 是否抬高交互延迟）。
- **反例**：若 uTP-only 的**可达 peer 数**与 TCP-only 相同，则「uTP 提高可达性」在本环境不成立；若 uTP 抬高带载 RTT 而不提高 goodput，则成本大于收益。
- **资源护栏**：`M-GUARD-06`（UDP drops）。
- **所需授权**：整形 + 受控对端 transport 能力配置。

**E2-4 MSE / PE 协商**
- **假设**：MSE 协商引入额外往返与失败路径；启用与否改变握手成功率与首字节时延，且在部分对端上增加失败类别。
- **操纵量**：MSE 模式（禁用 / 启用 / 强制）与受控对端能力矩阵。
- **固定量**：其余同 E2-3。
- **主终点**：`M-CONN-03/04/07`、`M-START-02`。
- **反例**：必须能观察到「TCP connect 成功 + MSE/BT 握手失败」的 attempt：该 attempt 只增加 `M-CONN-02` 的 transport success，**不**增加 `M-CONN-07` 的握手成功。若实现无法区分，本臂结论作废（先回 E0-D）。
- **资源护栏**：`M-GUARD-03`。
- **所需授权**：受控对端 + MSE 能力矩阵。

**E2-5 NAT / IPv6 / UDP 可达性**
- **假设**：NAT 映射与过滤行为（RFC 4787/5382 语义）、CGN（RFC 6598）与 IPv6 可用性决定**入站**可达性与打洞可行性；「有 IPv6 地址」不等于「IPv6 peer 可达」。
- **操纵量**：受影响端的 NAT 类型（受控：全锥 / 受限锥 / 对称 / CGN 模拟）；IPv4-only / IPv6-only / 双栈；UDP 是否放行（分端点）；是否启用端口映射（UPnP/PCP/NAT-PMP，若可用）。
- **固定量**：内容与候选供给固定；对端具备已知映射能力。
- **主终点**：`M-CONN-02/05/06`、入站连接数与 `M-PEER-03`（地址族分布）；护栏 `M-GUARD-06`。
- **反例**：一次 bootstrap 失败**不代表** DHT 整体失效；分端点 UDP 结果不能外推到全部 UDP。必须分别报告每个端点的结果。
- **资源护栏**：受控 NAT 设备资源。
- **所需授权**：受控 NAT/网络拓扑（**另行授权**，不得改动生产网络）。

**E2-6 竞争交互流**
- **假设**：BT 流与前台交互流（网页/游戏式小流）共存时存在 goodput 与排队延迟的 Pareto 取舍；无 AQM 时 bufferbloat 会使交互不可用。
- **操纵量**：AQM 开关（无 / `fq_codel` / `cake`）；并发交互流强度（空载 / 中等 / 重）。
- **固定量**：BT 侧固定（同 E2-3 混合档）。
- **主终点**：**护栏即主终点**：`M-GUARD-01`（带载 RTT 差）；辅：`M-GOODPUT-01`。
- **反例**：高 goodput 但交互延迟翻数倍**不算优秀**；若只报 goodput，本臂无意义。
- **资源护栏**：`M-GUARD-01/02`。
- **所需授权**：中间盒 qdisc 控制。

### 4.3 E2 附加矩阵（NAS / 移动端，仅列协议与条件，不伪造读数）

| 附加 | 操纵量 | 主终点（护栏优先） | 前置条件/授权 |
|---|---|---|---|
| NAS · 空闲静默 | 空闲期长度（≥10 min）；是否启用定时文件跟踪扫描 | `M-NASMOB-01`（空闲期磁盘 I/O 次数与队列延迟） | NAS 设备 + 只读采集（**另行授权**） |
| NAS · 机械盘 | 目标介质（HDD vs SSD）；做种并发 | `M-GUARD-07/08`、`M-GOODPUT-01` | 设备 + cgroup I/O |
| 移动 · 后台 | 前台/后台/锁屏；Doze/App Standby 状态；充电与否 | `M-NASMOB-02/03` | 真机 + 平台 API（**另行授权**） |

## 5. E3 · 合法公网生态验证

**目的**：在受控实验之外，检验可迁移性边界。**E3 不替代 E1/E2 的因果识别**。

### 5.1 swarm 类型与接入分层

| 维度 | 取值 | 记录要求 |
|---|---|---|
| swarm 类型 | 热门健康 / 低 seed 稀缺 / 高 churn | 健康度与供给作为 run-level 协变量 |
| 接入 | 国内同运营商 / 国内跨运营商 / 教育网 / 海外东亚 / 海外欧洲 / 海外北美 / 跨境 | **具体路径**与对端 AS、地区、时段 |
| 地址族 | IPv4 公网 / IPv4 NAT / CGN / IPv6 / 双栈 | NAT/过滤证据、DNS 答案、路由与代理出口 |
| 内容授权 | 仅合法授权内容 | 无授权不得纳入 |

**禁止**：把 AS/地区标签当作实测路径；把跨境慢直接归因审查或 P2P 限速；用 VPN 出口冒充本地接入；把 tracker 报的 seeders 当作可连 seeders；把 peer ID 自报当作可信客户端鉴定；用稳定 IP 哈希跨会话跟踪个人。

**private swarm** 只在站点允许且用户**另行授权**时纳入。

### 5.2 E3 实验卡（示例结构，全部需要另行授权）

**E3-1 公网健康 swarm · 版本/配置对照**
- **假设**：在健康 swarm 上，E1 观察到的预算/窗口效应会被高涨的供给淹没（即受控实验的效应在公网不可迁移）。
- **操纵量**：单个可复现的配置差异（例如预算档、uTP 开关、MSE 模式）——**每次只一个**。
- **固定量**：同一 torrent、同一目录策略、同一 tracker/DHT 设置、同一限速、同一时间窗、同一构建。
- **主终点**：`M-COMPLETE-01`、`M-START-03`、`M-GOODPUT-05`。
- **反例**：若差异在健康 swarm 消失，则受控实验效应**不可外推**到公网——这是本实验最有价值的结果之一，必须如实报告而不是换成「仍然有提升」的措辞。
- **资源护栏**：`M-GUARD-03/04/05`。
- **所需授权**：公网合法内容 + 真实运行（**另行授权**）。

**E3-2 低 seed 稀缺 swarm**
- **假设**：稀缺 swarm 上限制来自**供给**而不是调度；此时提高预算/窗口无收益，只有更多来源（tracker/DHT/PEX/LSD）才有收益。
- **操纵量**：来源集合（如 DHT 开/关、tracker-only）。
- **固定量**：其余同 E3-1。
- **主终点**：`M-DISC-01/02/03`、`M-PEER-07`、`M-START-03`。
- **反例**：若加入某来源后 `M-DISC-02`（去重后候选）不增，则该来源在当前环境**无贡献**；不得用「请求数变多」冒充贡献。
- **所需授权**：同 E3-1。

**E3-3 高 churn swarm**
- **假设**：churn 使「完成比例」比「均速」更能区分实现优劣；此时只看成功者均速会得出错误排序。
- **操纵量**：无（观察式）；或单个配置差异。
- **固定量**：观察期 `tau` 固定并预先声明；连接释放策略固定。
- **主终点**：`M-START-04`（`tau` 内完成比例）、`M-COMPLETE-04`（失败/超时/放弃比例）、`M-PEER-07`。
- **反例**：若实现 A 的 10 个 run 只有 1 个完成而 B 的 10 个都完成，**不得**只用 A 完成 run 的均速宣称 A 更快；必须报告完成比例与删失。
- **所需授权**：同 E3-1。

### 5.3 交叉顺序与样本量

- **配对方式**：随机 AB/BA 分块。每个时间块内随机决定 A→B 或 B→A，避免「永远先 A」引入的顺序/时段效应。
- **每核心条件**：先做 6 个独立配对，分散**至少 3 个时间块**。
- **正式样本量**（配对设计，由 pilot 校定）：
  $$n_{\text{pairs per block}} \ge \frac{2\,(z_{\alpha/2}+z_{\beta})^2\,\sigma_d^2}{\delta^2}$$
  其中 $\sigma_d^2$ 来自 pilot 的**配对差**方差，$\delta$ 是预先指定的最小可检测效应。若 $\sigma_d^2$ 未知则用 pilot 的差值 IQR 反推。
- **不合并异质 MB/s**：不同文件大小 / 接入带宽 / 计时口径 / 完成定义下的 MB/s 不直接汇总，**不做伪元分析**。

### 5.4 分析方法

1. **主分析**：每 run 原始值 → 配对差与比值 → 按时间块的**分层**中位数与 IQR → 分层 bootstrap 置信区间（重采样单位 = 独立配对块 / session / swarm）。
2. **删失**：行政截止未完成记右删失；用生存口径（Kaplan–Meier 类）报完成比例随时间，而不是把删失 run 丢弃。
3. **竞争事件**：终止性错误 / 用户取消 与「仍在运行」分开建模或单列，不当作无信息删失。
4. **少样本分位**：`n` 小不报 p99；分位数只在固定窗口聚合上算，不做无界历史数组。
5. **护栏优先**：任何 goodput 提升都必须在护栏未触发的子集内成立；护栏触发的 run 标为**中断**并单列，不进入主比较。

### 5.5 中断规则（护栏触发即中断）

阈值候选默认，**必须在 run 前固定**；触发即标记 run 为中断并保留原始数据，**禁止静默换参**继续。

| 护栏 | 触发条件（候选默认） | 动作 |
|---|---|---|
| 交互延迟 | 带载 RTT 差 > 空载 + 150 ms 且持续 ≥30 s | 中断；标 `interaction_guard` |
| 内存 | RSS 增长 > 基线 2× 或 > 1024 MiB | 中断；标 `memory_guard` |
| 句柄 | FD 使用 > `RLIMIT_NOFILE` 的 80% | 中断；标 `fd_guard` |
| 磁盘 | 队列延迟 > 2000 ms 持续 ≥30 s | 中断；标 `disk_guard` |
| CPU | 单核持续 100%（记录为瓶颈而非中断） | 继续但标注 `cpu_bound` |
| 隔离 | 检测到非受控 peer 进入受控 swarm | **立即**中断全部 run；标 `isolation_breach`（E1 有效性问题） |

### 5.6 鲁棒性实验臂（与主对照分开）

| 臂 | 操纵量 | 记录 |
|---|---|---|
| R1 手动暂停 | 在固定进度点暂停后再恢复 | `M-RECOVER-01/_02`、暂停期间残留流量；该 run **不进**无干预整程主比较 |
| R2 重启 | 在固定进度点强制重启进程 | `M-RECOVER-02/_03/_04/_05`、重校与重下字节 |
| R3 网络切换 | 传输中切换网络（Wi-Fi↔有线、IPv4↔IPv6） | `M-START-03`、`M-CONN-*`、`M-PEER-03` |
| R4 删失压力 | 缩短 `tau` 观察 | `M-START-04` 对 `tau` 的敏感性 |

**若污染了无干预整程**：保留该 run 并**标记为有干预**；不能只扣暂停时间就恢复因果可比性。
